# Golden Principles (kuro_keyviewer 적용)

> 코드를 읽거나 쓸 때 항상 걸리는 원칙. 다른 규칙 문서에 있는 것은 중복하지 않는다.
> 불변성·컴포넌트 규칙 → tsx-rules.md | Rust 관례 → rust-rules.md | TDD 절차 → ui-design-strategy / core-design-strategy

## 1. 작은 파일, 작은 함수

한계를 넘으면 분리한다. "조금 넘었다"는 예외가 아니다.

| 대상 | 파일 한계 | 함수 한계 |
|---|---|---|
| Rust (`.rs`) | 800줄 | 50줄 |
| React 컴포넌트 (`.tsx`) | 400줄 | 50줄 |
| TS 모듈 (`.ts`) | 400줄 | 50줄 |

- 예외: 자동 생성 파일(`src-tauri/gen/`, Vite 산출물), 테스트 픽스처·스냅샷, 데이터 상수 파일.
- Rust에서 함수가 길어지면 `impl` 블록의 private 메서드로 쪼갠다. React에서는 서브 컴포넌트나 커스텀 훅으로 뺀다.

## 2. 결론 먼저, 근거 나중

첫 문장에 결론. 그 다음에 "왜냐하면"을 붙인다. 보고·리뷰·설계 문서 모두 같다.

## 3. 비유로 설명

기술 개념을 설명할 때는 일상 비유 1~2문장을 먼저 두고 기술 설명을 뒤에 둔다.
예: "저수준 훅은 우체국 앞에 서서 모든 편지를 먼저 보는 검사원이다. 편지를 열어보되 반드시 다음 사람에게 넘긴다(CallNextHookEx)."

## 4. 컨텍스트 50% 규칙

대형 작업은 단계별로 나누어 새 세션에서 실행한다.
- core 모듈 1개의 설계 + 구현 + 테스트를 한 세션에 몰지 않는다.
- 화면 1개(overlay 또는 settings)의 설계 + 구현 + 테스트도 마찬가지다.
- 검증(verify-manager)은 별도 세션을 권장한다.

## 5. 증거 기반 완료

"이렇게 하면 작동할 것입니다"는 금지. 추측성 완료 선언은 거짓이다.
완료 보고에는 실행 증거를 붙인다.

| 계층 | 증거 |
|---|---|
| core (Rust) | `cargo test` 결과(테스트 수·PASS), `cargo clippy` 경고 0, `cargo check` exit 0 |
| bridge | Rust 구조체 ↔ TS 타입 대조표, `yarn tsc --noEmit` exit 0 |
| ui (React) | `yarn test --run` 결과, `yarn build` exit 0, 스크린샷 경로(`doc/300_검증/screenshots/…`) |

## 6. unsafe 격리

- `unsafe`는 `src-tauri/src/hook/` 안에서만 쓴다. 다른 모듈은 hook이 내놓은 안전한 API만 호출한다.
- 모든 `unsafe` 블록 위에 `// SAFETY:` 주석으로 "왜 안전한가"를 적는다(Windows API 문서 조건 인용).
- hook 밖에서 네이티브 호출이 필요해지면 hook 모듈에 안전한 래퍼를 추가하는 것이 정답이다. 훅(`kuro-unsafe-scope-guard.sh`)이 이를 강제한다.

## 합리화 방지

| 원칙 | 변명 | 현실 |
|---|---|---|
| 파일 크기 | "나눌 만큼 크지 않다" | Rust 800줄 / TSX 400줄 넘으면 분리 |
| 함수 크기 | "한 곳에 있어야 읽기 편하다" | 50줄 넘으면 이름 붙은 함수로 추출 |
| 결론 먼저 | "맥락 없이 결론이 어렵다" | 결론 한 줄 먼저, 맥락은 그 다음 |
| 컨텍스트 | "아직 여유 있다" | 대형 작업은 세션 분리 |
| 증거 기반 | "이미 잘 작동한다" | 실행 결과 없이 완료 = 거짓 |
| TDD | "너무 단순해서 테스트 불필요" | 상태 기계·검증 로직은 테스트 100% |
| unsafe | "여기서 한 줄만 부르면 편하다" | hook 밖 unsafe는 훅이 차단. 래퍼를 만든다 |
| 불변성 | "성능 때문에 mutation 필요" | 프로파일링 증명 후에만 허용 |
