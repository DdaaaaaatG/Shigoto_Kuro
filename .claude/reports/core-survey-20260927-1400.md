# core 현황 조사 — 데이터 세대 초기화(data-reset) 설계 입력 (2026-09-27 12:32, core-analyst, 읽기 전용)

## 0. 요약 (결론 먼저)

- 결론: 초기화에 필요한 부품은 대부분 이미 있다. 원자적 쓰기(`settings::write_atomic`), 설정 저장 창구(`settings::update`), 바이트 입력 등록(`assets::import_bytes`), 내장 기본 7장(`DEFAULT_ASSETS`), 에셋 변경 후처리(bridge `after_asset_change`)가 있다. **없는 것**은 세 가지다. ① 세대 표식(상수·해시·저장 필드 모두 없음), ② 폴더 통째 비우기 함수, ③ 설정 전체 교체 뒤 런타임 재적용 묶음(현재 `set_settings` 명령 본문에 흩어져 있음).
- 실제 데이터 폴더는 `%APPDATA%\com.kuro.keyviewer\`다(identifier 기준). CLAUDE.md와 스킬 §6에 적힌 `%APPDATA%\kuro_keyviewer\`와 다르다.
- 시작 시 초기화를 넣을 자리는 `lib.rs:96`(create_dir_all)과 `lib.rs:97`(seed) 사이다. 이 시점에는 AppState·창·훅이 아직 없으므로 파일 작업만 하면 된다.
- 실행 중 초기화(버튼)는 메모리 상태 3개(`settings`·`hand_anchor`·`timer`)와 창 속성(크기·위치·표시·잠금·작업표시줄), 이벤트 4종(settings/assets/hand-anchor/timer)을 다시 맞춰야 한다. 훅 스레드는 설정·에셋을 참조하지 않으므로 손대지 않아도 된다.
- 문서↔코드 불일치 7건(MEDIUM 4 / LOW 3), 표준 이탈 2건(HIGH 1 = PNG 비원자적 쓰기, MEDIUM 1 = settings `version` 부재. 부재는 설계 D19에서 의도한 것).

심각도 건수(참고 지적): CRITICAL 0 / HIGH 1 / MEDIUM 5 / LOW 3

### Q6. 자동 실행

- 방식: **작업 스케줄러**, `schtasks.exe`(절대 경로 autostart.rs:61-63), 작업 이름 `pub const TASK_NAME: &str = "kuro_keyviewer";`(:37), XML 등록 `build_task_xml`(:165). 레지스트리는 쓰지 않는다.
- 시그니처:

- 판단 근거:
  - **시작 시 초기화:** settings.json을 기본(autostart=false)으로 써도 같은 실행의 :165 보정 스레드가 작업이 있으면 true로 되돌린다. 어긋남은 몇 초 만에 해소된다.
  - **버튼 초기화:** 보정은 시작 시 1회뿐이라, false로 쓰면 다음 재시작 전까지 설정 창 표시와 실제 등록이 어긋난다. 선택지는 두 가지다. (a) `keep_core_owned`처럼 현재 autostart를 유지한다(OS 상태 불변, 어긋남 없음). (b) `set_enabled(false)`를 별도 스레드에서 호출한 뒤 `persist_autostart`로 저장한다. 사실관계상 (a)가 기존 소유권 규칙(tray.md §7)과 맞는다. 결정은 designer 몫이다.

### Q7. 창 위치·크기 저장

- 위치: `settings.overlay.{x,y,visible}`(settings.json 안). 별도 파일은 없다. 이동은 500ms 디바운스 뒤 `persist_overlay_position`(placement.rs:224)으로 저장된다. 시작할 때 `restore_overlay_position`(placement.rs:101)이 화면 밖이면 보정하고 저장한다(lib.rs:310-324).
- 크기: **저장하지 않는다.** 매번 `canvas × scale`로 계산한다(sizing.rs:54·70). 설정 창 크기·위치도 저장하지 않는다(conf 900×640, tauri.conf.json:35-36).

### Q8. 로그

- `log` 0.4 + `env_logger` 0.11(Cargo.toml:22-23), 초기화 코드는 `env_logger::Builder::from_env(Env::default().default_filter_or("info")).init()`(lib.rs:68). **stderr 출력만 하고 파일 로그는 없다.** 앱 데이터 폴더에 로그 파일은 없다. 진단 target `kuro_diag`(lib.rs:11-13)도 있다.

## 7. 확인 필요 (관리자에게)

1. 초기화 범위에 `assets/alarm.*`(사용자 알림음, CR-048)를 넣을지. 요구 문구는 "그림 전부 + manifest + settings.json"이라 알림음은 명시되지 않았다.
2. 버튼 초기화 때 `autostart`와 실제 작업 등록을 유지할지 해제할지(Q6).
3. 기본 좌표(shoulder·part_pos·pen_pos·timer text_pos)가 CR-053 내장 세트에 맞게 조정됐는지. 주석은 CR-044 기준이다.
4. 세대 표식을 둘 곳(settings.json 필드 추가 시 D19 재검토, 별도 마커 파일, manifest 필드)과 세대 값의 정의(수동 상수 / 내장 바이트 해시 / 앱 버전). 현재 앱 버전(0.1.0)은 세트 교체와 연동되지 않는다.
5. WebView2 데이터·ui localStorage(core 밖)를 초기화 대상에 넣을지.
