# core 현황 조사: 내장 기본 PNG 세트(시딩·슬롯 복원·내보내기) 설계 준비 (2026-09-24 23:27, core-analyst, 읽기 전용)

목적은 현황 수집이다. 판정과 설계 제안은 넣지 않고, 사실만 파일:줄 근거와 함께 적는다. 요구 추적은 하지 않았다(요구ID 목록을 받지 않음).

## 0. 요약

- assets의 저장 API(`import`)는 **파일 경로만** 받는다. 검증 함수 두 개(`parse_png_header(&[u8])`, `validate(&PngInfo, u64, …)`)는 메모리 바이트로 쓸 수 있다. 다만 그룹 기준 크기를 구하는 `group_size`와 `recompute_canvas`는 비공개다.
- 첫 실행을 감지하는 로직, `include_bytes!`, `bundle.resources`, `tauri-plugin-fs`, settings `version` 필드는 **모두 없다**.
- 실제 앱 데이터 경로는 `%APPDATA%\com.kuro.keyviewer\`다(identifier 기준). CLAUDE.md와 스킬에 적힌 `kuro_keyviewer`와 다르다.
- `doc/assets/defaults/`에는 PNG 15장과 `manifest.snapshot.json`이 있다. 이 세트에 **body.png는 없다**.

## 2. 질문별 사실

### Q1. assets 공개 API

`mod.rs:14-16`이 재노출한다. `mod.rs:54-56`에서 `compute_hand_anchor`와 슬롯 타입, `asset_url`을 `pub use`한다.

- `pub fn parse_png_header(bytes: &[u8]) -> Result<PngInfo, AssetError>` (mod.rs:175)
  - **메모리 바이트**를 받는다. 시그니처와 IHDR만 읽으며 최소 29바이트가 필요하다.
- `pub fn validate(info: &PngInfo, bytes: u64, slot: &AssetSlot, group_size: Option<CanvasSize>) -> Result<(), AssetError>` (mod.rs:198-203)
  - 경로도 바이트도 받지 않는다. 헤더 정보와 **용량 숫자**, 기준 크기만 받는 순수 함수다.
  - 검사 순서: RGBA(204) → 1MB(207) → 0 < 크기 ≤ 900×700(211) → 그룹 크기 일치(219-222).
- `fn group_size(manifest, slot) -> Option<CanvasSize>` (mod.rs:253)
  - **비공개**다. 같은 그룹에서 이 슬롯을 뺀 나머지가 정하는 기준 크기를 돌려준다.
- `AssetManifest::recompute_canvas` (mod.rs:98)도 **비공개**다.
- `pub fn load_manifest(assets_dir: &Path) -> Result<AssetManifest, AssetError>` (mod.rs:282)
- `pub fn save_manifest(assets_dir: &Path, manifest: &AssetManifest) -> Result<(), AssetError>` (mod.rs:290)
  - `.tmp`에 쓴 뒤 기존 파일을 `remove_file`하고 `rename`한다(294-298).
- `pub fn import(assets_dir: &Path, slot: AssetSlot, src: &Path) -> Result<AssetManifest, AssetError>` (mod.rs:303)
  - 입력은 **파일 경로**다. 내부 순서:
    1. `fs::read(src)`(304)
    2. 헤더 파싱
    3. 매니페스트 로드
    4. `group_size`로 기준 크기 계산 → `validate`
    5. `assets/{file_key}.png`에 `fs::write`로 직접 씀(314, tmp와 rename 없음)
    6. 같은 슬롯 항목을 교체(324-327)하고 `recompute_canvas`
    7. `save_manifest`
  - 바이트를 받는 import 변형은 **없다**.
- `pub fn remove(assets_dir: &Path, slot: AssetSlot) -> Result<AssetManifest, AssetError>` (mod.rs:333)
  - 해당 슬롯 하나만 지운다. 항목이 없으면 `NotFound(key)`(340-341)다. 파일이 있으면 삭제하고 캔버스를 다시 계산한 뒤 저장한다.
- `pub fn asset_url(path: &Path) -> String` (url.rs:17)
  - `versioned_asset_url`(url.rs:24, `?v={mtime ms}`)은 `pub(super)`라 모듈 밖에서 쓸 수 없다.
- 공개 타입과 상수:
  - 타입: `CanvasSize`(69), `AssetEntry{slot,file_name,width,height,bytes,url}`(76-83), `AssetManifest{canvas,entries}`(87-90, 필드 pub, Default), `AssetManifest::find`(93), `PngInfo`(167)
  - 상수: `CANVAS_MAX_WIDTH=900`, `CANVAS_MAX_HEIGHT=700`, `ASSET_MAX_BYTES=1048576`, `MANIFEST_FILE="manifest.json"`(58-61)

### Q2. 슬롯 모델 (slot.rs)

- `SimpleSlot`(slot.rs:22-51)은 23개다.
  - 캔버스 레이어: background, body, idle, rest, kb_up, key_space, key_z, key_question, key_exclamation, key_enter, key_backspace, key_undo
  - 마우스 파츠: mouse_base, mouse_left, mouse_right
  - 펜 그룹: pen_up, pen_key_space, pen_key_z, pen_key_question, pen_key_exclamation, pen_key_enter, pen_key_backspace, pen_key_undo
- 여러 장 슬롯
  - `AssetSlot::KbDown{kind,index:u32}`: JSON은 `{"kind":"kb_down","index":N}`, 파일 키는 `kb_down_{index}`(slot.rs:72-75, 128)
  - `AssetSlot::PenDown{kind,index}`: JSON은 `{"kind":"pen_down","index":N}`, 파일 키는 `pen_down_{index}`(77-80, 129)
  - enum은 `#[serde(untagged)]`다(69).
- 파일명은 `format!("{}.png", slot.file_key())`(mod.rs:312)로 정한다. 단순 슬롯의 키는 serde 이름과 같다(100-127).
- 분류 함수
  - `is_mouse_part`(134): mouse 3개
  - `is_pen_part`(142): pen_* 8개와 PenDown
  - `is_canvas_layer = !mouse && !pen`(160-162)
- 여러 장 슬롯의 삭제 규칙이 core에는 **없다**.
  - `remove`는 전달된 슬롯 키 하나만 지운다(mod.rs:333-351). 번호를 당기거나 "마지막 장만" 지우게 제한하는 코드가 없다.
  - `index`에 상한이나 연속성 검사도 없다. `import`도 임의 index를 받는다.
  - 순번 관리가 ui 쪽에 있는지는 core 범위 밖이라 확인하지 않았다.

### Q3. 캔버스 결정 규칙

- 캔버스는 `entries`에서 **처음 나오는 캔버스 레이어**의 크기다(mod.rs:98-107, 문서주석 26-29).
  - 마우스 파츠와 펜 그룹은 캔버스에 참여하지 않는다.
  - 각 그룹은 그룹 안에서 첫 항목 크기를 기준으로 쓴다(mod.rs:262-277의 `find`).
- 캔버스 레이어가 모두 비면 `canvas=None`이다(recompute_canvas가 None을 돌려줌. 테스트 mod.rs:484-486).
- 다른 캔버스 레이어가 있을 때만 캔버스가 기준이 된다(mod.rs:256-261). 따라서 **유일한 캔버스 레이어를 다른 크기로 교체하는 것은 허용**된다(테스트 474-482).
- 크기가 맞지 않으면 그룹별 에러가 난다(mod.rs:226-250).
  - `CanvasMismatch{w,h,cw,ch}`
  - `MousePartMismatch{w,h,mw,mh}`
  - `PenPartMismatch{w,h,pw,ph}`
  - `code()`는 셋 다 `asset.canvas_mismatch`다(153-155).

### Q4. 매니페스트 위치와 부재·손상 시 동작

- 경로는 `app.path().app_data_dir()` + `assets/manifest.json`이다(lib.rs:36-39, mod.rs:61·283).
  - identifier가 `com.kuro.keyviewer`(tauri.conf.json:5)라서 실경로는 `%APPDATA%\com.kuro.keyviewer\assets\manifest.json`이다.
  - lib.rs:26과 settings/mod.rs:3 주석, defaults 스냅샷의 url도 같은 경로를 가리킨다.
- 파일이 없을 때: `Ok(AssetManifest::default())`를 돌려준다(canvas None, entries 빈 배열, mod.rs:284-286). 이때 파일을 만들지 않는다.
- entries가 빈 배열일 때: 저장된 `canvas`를 그대로 쓴다. 건너뛴 항목이 있을 때만 캔버스를 다시 계산한다(manifest_load.rs:27-33).
- 항목 하나를 해석하지 못할 때: 그 항목만 경고 로그를 남기고 건너뛴다(manifest_load.rs:38-50).
- 최상위 구조가 손상됐을 때: `Err(AssetError::Manifest)`(manifest_load.rs:24). 호출 지점마다 처리가 다르다.
  - 시작 시: 경고를 남기고 기본값(빈 매니페스트)으로 처리하며, 파일은 고치지 않는다(lib.rs:68-71).
  - `load_manifest_or_warn`(commands.rs:49-50): 경고를 남기고 기본값을 쓴다.
  - `get_asset_manifest`: 에러를 반환한다(commands.rs:202).
  - `import`와 `remove`: 내부에서 `load_manifest?`를 부르므로(mod.rs:306·334) **손상이 남아 있으면 등록과 삭제가 모두 실패**한다.
- **첫 실행 감지 로직은 없다.** src 전체에서 first·seed·version·defaults를 검색해 관련 코드가 없음을 확인했다.
  - settings도 파일이 없으면 기본값을 메모리에만 두고 저장하지 않는다(settings/mod.rs:225-237, lib.rs:67).
