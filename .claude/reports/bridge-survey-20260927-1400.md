## 5. 확인 필요 (사용자 판단)

1. **core 소유 필드의 초기화 범위** — `overlay.x/y`는 `reset_overlay_position`(기본 (100,100))이 따로 있고, `autostart`는 작업 스케줄러 실제 등록 상태와 `settings.json` 값이 짝이다(`contract.md:914`·`1016`). settings.json만 기본(`autostart: false`)으로 덮으면 스케줄러 등록은 남아 불일치가 생길 수 있다 — 초기화에 자동 실행 해제를 포함할지.
2. **알림음 포함 여부·알림 방법** — 「그림 전부」에 `assets/alarm.*`가 포함되는지, 포함하면 열린 설정 창에 어떻게 알릴지(이벤트 없음).
3. **첫 실행 시딩 재사용** — `seed_if_empty`는 매니페스트가 비었고 기본 파일명이 폴더에 없어야만 동작한다(`defaults.rs:110-123`). 초기화 흐름이 이 조건을 만족시킨 뒤 호출할지, 무조건 시딩 함수를 새로 둘지는 core 결정.
4. **이벤트 순서** — 기존 규칙은 주 이벤트 → 손 기준점 → 타이머(`contract.md:887`·`923`). 설정과 에셋이 동시에 바뀌는 첫 사례라 `settings://changed`와 `assets://changed` 사이 순서 규칙이 계약에 없다.
5. **동기/비동기** — 파일 다수 삭제·7장 쓰기는 메인 스레드를 잠시 막는다(`export_default_assets`의 같은 우려 `contract.md:1062`). 손 기준점·리사이즈는 메인 스레드 전제(§5.1-7)라 async로 하면 그 전제를 다시 설계해야 한다.
