  - 분리 방안(방향):
    a) index.tsx 렌더에서 `const motion = wrapMotion(machine)`을 한 번 계산해 .jellyWrap과 새 헤어 래퍼 둘 다에 같은 값을 준다(같은 커밋에서 두 요소 클래스가 동시에 바뀜 → 같은 프레임의 스타일 재계산에서 애니메이션 시작 = 동기).
    b) 새 헤어 래퍼는 `.canvas`의 **첫 자식**(BackgroundLayer 앞)에 둔다. 클래스 = 새 기본 클래스(예 `.hairWrap`) + 같은 수식 클래스(.jelly/.jellyAlt/.shiver). jellyClass를 `(motion, base)` 형태로 일반화하거나 동등 함수로.
    c) `.hairWrap` 기하는 `.jellyWrap`과 **완전히 동일**해야 함: absolute·left/top 0·width/height 100%·pointer-events none·transform-origin 50% 100%(그룹 선택자 `.jellyWrap, .hairWrap` 또는 composes). 두 래퍼 모두 `.canvas` 직계 자식이라 100% = canvas.width×canvas.height(px) → transform-origin 기준점 픽셀 좌표가 같음. .canvas의 scale은 부모에 있어 둘 다 동일하게 받음.
    d) 기본 클래스 이름으로 `.jellyWrap`을 **재사용하지 말 것**: 테스트 헬퍼가 `querySelector('.jellyWrap')`(첫 일치)로 본체 래퍼를 찾음(OverlayApp.hair.test.tsx:186 등) — 헤어 래퍼가 DOM상 앞이라 첫 일치를 빼앗는다.
    e) 헤어 래퍼는 **hair 항목이 있을 때만** 렌더 권고(`findEntry(manifest,'hair')` 존재 시 `<div class=hairWrap…><HairLayer/></div>`). 무조건 렌더하면 `.canvas` 자식 목록을 단언하는 overlay 테스트 11개 파일(18곳 — jelly·shiver·pen·penClick·penToggle·pomodoro·timerMode·TimerText.blink 등)이 헤어 없는 픽스처에서도 깨진다. HairLayer 자체는 img만 내도록 유지하면 TC-238~240 불변.
    f) 조건부 렌더의 작은 비동기: 젤리 350ms 도중에 hair가 새로 등록되면 새 래퍼는 그 시점부터 재생(본체와 수백 ms 어긋남, 다음 키 누름에서 다시 맞음). 부르르 중 등록 시 80ms 주기 위상차 가능. 허용 여부는 의도 질문 참조.
    g) 헤어 img 자체에는 여전히 클래스 `layer` 하나·인라인 style 없음(기존 규칙 유지).
