## 1. 개요

설정 창은 오버레이와 떨어진 「조종실」이다. 여기서 값을 바꾸면 bridge가 저장하고 `settings://changed`로 오버레이에 알린다.

- 창 라벨 분기: `src/main.tsx`가 창 라벨이 `settings`이면 `./settings`를 지연 로딩하고 `document.body.dataset.window = 'settings'`를 넣는다(등록 완료, 신규 창 아님).
- (CR-028) 탭 3개: **기본 설정 / 이미지 설정 / 어깨축·손 위치**(R-19). 기본 탭 = 기본 설정. 탭 바는 채택 패턴의 기본 요소다. 각 탭 상세: 기본 설정 = `design/general-tab.md`, 이미지 설정 = `design/images-tab.md`, 어깨축·손 위치 = 이 문서 §4·§5.1·§5.2·§10(옛 「마우스 파츠」 탭 그대로 — R-26). 문구 3개 국어 = `design/i18n.md`.
- 참고 화면에서 가져오지 않는 것(R-19 금지 조건): 제품명·제작자·버전 머리글, 닫기·설명서 버튼, 프리셋 탭, 크기 4단 버튼, 흔들림, 항상 위에 고정. 창 닫기는 OS 제목 표시줄.
- (CR-028 이전 기록 — 폐기) 탭 3개(이미지 / 동작 / 마우스 파츠). 현재 기능이 있는 탭은 「마우스 파츠」뿐이다. 「이미지」는 등록 목록 읽기 전용, 「동작」은 설정 JSON 덤프 읽기 전용 — 둘 다 **R-03·R-04·R-06·R-14 보류 기간의 임시 표시**다(🔒 2026-09-23. R-05는 CR-020으로 폐기). 다음 단계에서 각 요구의 설계로 교체한다. 탭 바는 채택 패턴의 기본 요소라 요구 범위 안이다.

## 9. 접근성

- (CR-031, R-27) 세로 메뉴: `role="tablist"` + `aria-orientation="vertical"` + `aria-label={t.tabsAria}`, 항목 `role="tab"` + `aria-selected` + `aria-controls`, 본문 `role="tabpanel"` + `aria-labelledby`. **로빙 tabindex** — 선택 항목만 `tabIndex=0`, 나머지 `-1`이라 Tab 키로는 메뉴에 한 번만 들어간다. 메뉴 안 이동 = **위·아래 화살표**(끝에서 순환)·Home·End, 이동하면 그 탭이 바로 선택된다(자동 활성, §5.3 `onTabKeyDown`). **좌·우 화살표는 쓰지 않는다** — 기존 설계에는 화살표 규칙이 없었고(가로 탭 바는 Tab 키로 버튼 하나씩 이동), 이번에 대체할 좌우 규칙은 없다. 세로 방향이라 위·아래만 둔다. 아이콘은 `aria-hidden="true"`(이름은 글자 `tabLabel`이 준다). 포커스 순서(Tab): 선택된 메뉴 항목 → 탭 본문 첫 조작 요소(섹션 제목 `h1`·오류 줄은 포커스 대상 아님). 언어 전환 시 포커스는 그대로(글자만 바뀜). 선택 상태는 색만이 아니라 `aria-selected`와 굵기(700)로도 구분된다. 아래 CR-028 줄의 「탭 버튼 → 탭 버튼 → 탭 버튼」 순서와 「탭 버튼은 `aria-pressed`로 선택 상태를 알린다」는 이 줄로 **대체**한다.
- (CR-028) 포커스 순서(Tab): 탭 버튼 「기본 설정」 → 「이미지 설정」 → 「어깨축·손 위치」 → (오류 줄은 포커스 대상 아님) → 선택된 탭 내용. 기본 설정 탭 = `design/general-tab.md` §6, 이미지 설정 탭 = `design/images-tab.md` §8, 어깨축·손 위치 탭 = 아래 옛 「마우스 탭」 순서 그대로. 언어 전환 시 포커스는 그대로 둔다(문구만 바뀜). `<html lang>`이 바뀌어 화면 낭독기가 새 언어로 읽는다.
- (이전 기록) 포커스 순서(Tab): 탭 버튼 「이미지」 → 「동작」 → 「마우스 파츠」 → (마우스 탭) 단계별 버튼: idle = 「어깨축 설정하기」 → 「이동 영역 설정하기」(CR-018) → 「기본값으로 리셋」 / pickShoulder = 「취소」 / review = 「저장」 → 「취소」 / pickArea = 「취소」 / reviewArea = 「저장」 → 「취소」.
- 이동 영역 단계 포커스(CR-018): 아래 「단계 전환 후 포커스」 규칙을 그대로 넓힌다 — pickArea 진입 = 「취소」(`cancelPickRef`), reviewArea 진입 = 「저장」(`saveRef`), idle 복귀 = 「어깨축 설정하기」(`startRef`). pickArea 안에서 점이 늘어나는 동안은 단계가 같아 포커스를 옮기지 않는다(안내 줄 `aria-live`가 1/4~4/4를 읽는다). 이동 영역 꼭짓점 지정은 포인터 전용(키보드 대체 수단 없음 — 요구 없음), 결과는 값 목록 「이동 영역」으로 확인한다. 영역 선 SVG는 `aria-hidden="true"`.
- 단계 전환 후 포커스(**소스 미적용**): 마법사 단계(`wizard.step`)가 바뀌면 포커스를 **다음 단계의 첫 버튼**으로 옮긴다 — pickShoulder 진입 = 「취소」, review 진입 = 「저장」, idle 복귀(저장 성공·취소) = 「어깨축 설정하기」. 구현: 단계별 첫 버튼에 `ref`(`useRef<HTMLButtonElement>(null)`)를 달고 `useEffect(() => { 해당 단계 ref.current?.focus() }, [wizard.step])`. 첫 마운트(초기 idle)에서는 옮기지 않는다(이전 단계 값을 `useRef`로 보관해 값이 실제로 바뀐 경우만). 버튼이 `disabled`(saving)여도 `focus()` 호출은 그대로 둔다(저장 완료 시 `saved`로 idle이 되며 이때 `saving=false`).
- 키보드: 모든 버튼은 Enter·Space로 동작(네이티브 `<button type="button">`). 탭 버튼은 `aria-pressed`로 선택 상태를 알린다.
- 미리보기 클릭 지정과 손 그림 끌어다 놓기(CR-016)는 포인터(마우스) 전용이다(`role="presentation"`). 키보드 대체 수단은 요구에 없고 추가하지 않는다(메인 세션 결정 2026-09-23).
- 끌기 결과는 값 목록 「파츠 위치」 `dd`에 숫자로 보인다(화면 낭독기는 목록을 읽어 확인). 끌기 중 실시간 알림(`aria-live`)은 두지 않는다.
- 상태 알림: 안내 줄 `role="status" aria-live="polite"`가 단계 전환을 읽는다. 오류 줄 `role="alert"`(끌어다 놓기 저장 실패 포함). 축 마커 `role="img"` + 좌표 aria-label. 장식 이미지(바탕·손 그림)는 `alt=""`. 패드 박스는 없다(CR-016).
- 저장 중(`saving === true`) 「기본값으로 리셋」·「어깨축 설정하기」·「이동 영역 설정하기」(CR-018)·「저장」·「취소」는 `disabled`(포커스 순서에서 빠짐)이고 손 그림 끌기도 시작되지 않는다(CR-016). 저장이 끝나면 다시 활성.

## 10. 레이어·미리보기 명세

- 미리보기 합성 순서(아래→위, CR-016): 마우스 기본 파츠(`partPos`, 자연 크기 × `scale`, 회전 0°) → 바탕(`body`, 없으면 `kb_up`) → 축 마커. 오버레이의 z0(마우스 파츠) → z1 몸통 / z3 `kb_up` 순서와 같다. `body`가 있을 때 `kb_up`은 겹치지 않는다(바탕은 한 장).
- 미리보기 합성 순서에 헤어 추가(CR-037, R-34, 메인 세션 결정 2026-09-25): **헤어(`hair`, 캔버스 전체) → 마우스 기본 파츠 → 바탕 → 펜 손 → 이동 영역 선 → 축 마커**. 오버레이의 헤어 → 배경 → 뽀모도 → 팔 → 본체 → 펜 손 순서(CR-051 🔒 2026-09-26 — 헤어가 배경보다 아래로 바뀜)에서 배경·뽀모도만 뺀 것과 같다(미리보기는 원래 배경·뽀모도를 그리지 않는다 — 그래서 CR-051로 미리보기 순서·소스는 바뀌지 않는다). 헤어는 1장 고정이며 끌기·클릭·마법사 어느 단계에도 반응하지 않는다.
- 미리보기 합성 순서에 이동 영역 선 추가(CR-018): 마우스 기본 파츠 → 바탕 → **이동 영역 선(`AreaOutline`)** → 축 마커. 선은 `pointer-events: none`이라 클릭·끌기 판정에 영향이 없다.
- 이동 영역 선 표시 결정(CR-018, R-16 — 관리자 위임): **평소에도 표시한다.** 근거 ① 옛 패드 박스를 숨긴 이유(CR-006)는 레이어 이동 모드에서 패드가 손 위치와 직접 대응하지 않았기 때문인데, 이동 영역은 커서가 모니터 구석일 때 손 기준점이 가는 **목표점 자체**라 그림과 직접 대응한다 ② 저장 후 영역을 다시 확인할 수단이 선뿐이다(값 목록의 숫자만으로는 모양을 알기 어렵다) ③ 1px `#3b82f6` 선이라 바탕 그림을 가리지 않는다. 설정 중(pickArea·reviewArea)에는 저장된 선 대신 편집 선(2px + 점 표식)을 보인다.
- 모드: 하나(overlay R-18). 손바닥 모드 미리보기 규칙(보류였던 것)은 **폐기**(CR-016). 패드 박스는 **항상 숨김**(CR-006의 레이어 이동 모드 규칙을 전체 적용).
- 끌기 판정은 **좌표 기반**이다: 손 그림이 바탕 아래에 깔려 포인터를 받을 수 없으므로 미리보기 `div`가 포인터를 받아 `toCanvasPoint` → `hitPart`로 판정한다(§5.2). 투명 픽셀도 그림 사각형 안이면 잡힌다.
- 끌기 범위: 그림 전체가 캔버스 안(`clampPartPos`, 메인 세션 결정). 캔버스 전체 크기 그림은 (0, 0) 고정이라 끌어도 움직이지 않는다.
- 배경(`background` 슬롯, overlay R-17·CR-014): 어깨축 마법사 미리보기에 **넣지 않는다**(요구 없음). 합성 순서는 위 그대로다.
- 좌표: 미리보기 픽셀 = 캔버스 좌표 × `scale`. 클릭·포인터 → `previewToCanvas`로 캔버스 정수 좌표.
- 축 마커: 14px 원, 빨강 `#e53935`, 흰 테두리.
