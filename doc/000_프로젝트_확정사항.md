# kuro_keyviewer 프로젝트 확정사항 (단일 소스)

- 확정일: 2026-09-22 · 정리: 2026-09-28(§1·§3·§4·§5·§6의 옛 문장을 최신 🔒 결정에 맞춤, `doc/100_요구조건/parts-spec.md` 동기화)
- 이 문서는 `.claude` 자산(에이전트·스킬·훅·스크립트·명령)과 모든 설계 문서가 참조하는 **단일 기준**이다.
- 여기 적힌 값은 사용자가 확정한 것이다(🔒). 바꾸려면 사용자 확인 후 이 문서를 먼저 고친다.

## 1. 제품 정의

- **이름**: kuro_keyviewer
- **정체**: 봉고캣(Bongo Cat)류 키뷰어. 키보드를 치거나 마우스를 움직일 때 사용자가 넣은 이미지가 바뀌거나 움직이는 모션을 보여주는 **Windows 데스크톱 앱**.
- **실행 형태**: exe를 직접 실행. OBS 연동 없음. 화면 위에 투명 오버레이 창으로 떠 있음.
- **대상 OS**: Windows 10/11 전용.
- **UI 언어**: 한국어 기본. 설정 창은 한국어·일본어·영어 선택(🔒 2026-09-24, §6 설정 창 개편). 트레이 메뉴는 한국어 고정.
- **저장**: DB 없음. 사용자 이미지(PNG)와 설정(JSON)을 로컬 앱 데이터 폴더에 저장.

## 3. 이미지 규격 (🔒)

- 형식: **PNG 32bit RGBA만**. 다른 형식 거부.
- 모든 그림: 가로 ≤ 900, 세로 ≤ 700, 파일 ≤ 1 MB.
- **캔버스 레이어**(배경 `background`·뒷머리 `hair`·뽀모도 `pomo_char`·`pomo_bubble`·몸통 `body`·대기 `idle`·쉬는중 `rest`·키보드 `kb_up`·`kb_down_N`·특수 키 `key_*`): **서로 같은 픽셀 크기**여야 한다. 첫 업로드한 캔버스 레이어 크기가 캔버스 기준이 되고, 다른 크기는 거부한다. 캔버스 레이어를 모두 지우면 캔버스도 초기화된다.
- **파츠**(팔 `mouse_*`·펜 손 `pen_*`): 크기 자유 — 상한만 지킨다(CR-036). 캔버스 크기 규칙을 받지 않는다.
- **마우스 파츠 (🔒 2026-09-23 사용자 재정의, 이전 2모드 폐기):** 모드는 **하나**다. 팔(손 포함) 부분만 딱 맞게 그린 **작은 PNG**(투명 여백 불필요)를 캔버스 좌표 **위치 `partPos` (x, y)**에 놓고, **어깨 고정점을 축으로 그림 그대로 회전**시켜 손이 커서 목표점을 향하게 한다. 앱은 팔을 그리지 않는다(**손바닥 모드·앱이 그리는 팔 곡선은 폐기** — 사용자가 요청한 적 없음). 캔버스 전체 크기 그림을 넣으면 위치 (0, 0)으로 동작한다. 기본·왼클릭·오른클릭 파츠는 같은 위치(크기는 CR-036 이후 자유). **본체(몸통·키보드 그림) 아래에 깔린다.**
  - **이동 영역·팔 늘어나기 (🔒 2026-09-23 사용자 지정, CR-017):** 직사각형 패드 구역(`pad`)을 폐기하고 **자유 사각형 이동 영역**(`mouse.area`, 꼭짓점 4개: 왼쪽 위 → 오른쪽 위 → 오른쪽 아래 → 왼쪽 아래, 캔버스 좌표)으로 바꾼다. 설정 창 미리보기에서 네 점을 차례로 클릭해 지정. **커서가 있는 모니터 기준**으로 커서의 모니터 내 비율 (u, v)를 구해 영역의 네 꼭짓점에 쌍선형 보간한 점이 목표점. 팔은 어깨를 핀으로 **회전 + 팔 방향으로 늘어나기/줄어들기**(손 기준점이 목표점에 닿도록), 늘어나기 배율 **0.5~1.6배**로 제한. 쉬는 위치는 회전 0°·배율 1.
  - **펜 쥔 손 파츠 (🔒 2026-09-24 사용자 지정, CR-024):** 팔 파츠와 **별개의 작은 손 이미지**(선택). 팔 끝(어깨 축 반대쪽)에 붙으며, 사용자가 설정 창에서 **손 위치를 끌어다 놓아 조정**(`mouse.penPos`, 쉬는 자세 기준 캔버스 좌표). 팔이 회전·늘어나면 손은 **팔 끝 붙은 점을 따라 이동하고 팔과 같은 각도로 기울지만 크기는 늘어나지 않음**. **키보드 입력**(마우스 클릭 아님) 시 손 이미지만 교체해 펜으로 글씨 쓰듯 움직임: 평소 `pen_up`, 누름 `pen_down_0…`(여러 장이면 순환), 특수 키 전용 `pen_key_{special}`(있으면 그 그림, 없으면 `pen_down`). **손 이미지가 있으면 키보드 레이어는 `kb_up`에 고정**(kb_down·특수 키 kb 그림으로 바뀌지 않음 — 두 손이 동시에 움직이지 않게). 손 이미지가 없으면 기존 키보드 모션 그대로. 젤리·부르르는 기존대로 덩어리 전체. **마우스 클릭도 키 입력처럼 (🔒 2026-09-24 사용자 지정, CR-027):** 손 이미지가 있으면 왼·오른 클릭 누름도 키 누름과 똑같이 손을 `pen_down_N`(순환)으로 바꾸고 젤리 바운스를 낸다. 버튼을 떼면 `pen_up`(눌린 키·버튼이 남아 있으면 유지). 손 이미지가 없으면 클릭 동작은 기존 그대로(바운스 없음). **펜 손 사용 토글 (🔒 2026-09-24 사용자 지정, CR-033):** 펜 모드는 `pen_up` 등록 여부가 아니라 **설정 `mouse.penMode`(bool)**로 켜고 끈다. 이미지 설정 탭 손(펜) 그룹에 「펜 손 사용」 토글 + **항상 보이는 안내 상자**(펜 손을 쓰면 팔에 붙은 손 그림이 키보드 입력 때 바뀌고, 키보드 그림은 기본 그림에 고정된다는 설명) + **켤 때 확인창**(같은 설명, 켜기/취소). **`pen_up`을 처음 등록할 때 "펜 손 모드를 켤까요?" 확인창**을 띄워 예 → 켜짐, 아니요 → 꺼짐. **토글 꺼짐** = `pen_up` 그림은 팔 끝에 붙어 계속 따라다니되 바뀌지 않고, 키보드 입력은 키보드 그림(kb_down·특수 키 그림)으로. 클릭 바운스(CR-027)도 켜짐일 때만. `pen_up`이 없으면 토글은 비활성.
  - **위치 지정:** 설정 창 「어깨축·손 위치」 탭 미리보기에서 **팔 그림을 끌어다 놓아** 정하고 settings에 저장한다. 개발자가 끌어다 놓아 정한 좌표를 코드 기본값으로 옮긴다. 현재 기본값 = **(411, 464)**(CR-044). 이력: 초기 (389, 492)(예시 `mouse_pen_hand.png` 202×154 자리) — 옛 설정 파일에 `partPos`가 없을 때 채우는 마이그레이션 값으로만 남아 있다.
- 권장 제작 크기: **900×700** (비율 9:7 = 1.29:1, 기본 표시 450×350의 정확히 2배 — 정수 배율이라 축소가 선명하다). 봉고캣 원본 스킨(612×354, 비율 1.73:1)도 ≤900×700이므로 등록은 되지만 비율이 달라 상자에 여백이 생긴다. (2026-09-23 확정, 이전 1024×592 폐기)
- **표시**: 기본 **450×350** 상자에 비율 유지로 맞춤. 배율은 설정 창 슬라이더와 오버레이 위 Ctrl+휠로 조절하며, 범위는 **25%~200%**(200% = 900×700 원본 크기 그대로)다. 배율은 설정 JSON에 저장. **오버레이 창 크기는 표시 크기에 맞춰 자동 조절**된다(창 고정 아님 — 2026-09-23 확정).

## 4. 레이어 모델 (🔒, 아래에서 위로 겹침)

> 현재 겹침 순서 요약(아래→위, CR-051 기준): **뒷머리 → 배경 → 뽀모도 인물 → 말풍선 → 시간 글자 → 팔(마우스 파츠) → 본체 묶음(몸통 → 대기/쉬는중 → 키보드 그림) → 펜 손**. 젤리·부르르는 뒷머리·팔·본체 묶음·펜 손이 한 덩어리로 받고, 배경·뽀모도는 고정이다. 아래 표는 순서 번호로 위치를 적는다(마우스 파츠 행은 설명이 길어 키보드 파츠 뒤에 둔다).

| 순서 | 분류 | 이미지 | 크기 | 동작 |
|---|---|---|---|---|
| 1 | 뒷머리 (🔒 2026-09-25 추가 CR-037, 2026-09-26 맨 뒤로 CR-051) | 선택 1장 `hair` | 전체 캔버스 | 맨 아래. 상태·키 입력으로 바뀌지 않음. 젤리·부르르는 본체와 함께 |
| 2 | 배경 (🔒 2026-09-23 추가) | 선택 1장 `background` | 전체 캔버스 | 어떤 이펙트·반응(바운스·상태 교체·커서)도 받지 않고 항상 그대로. 비어 있으면 투명 |
| 3 | 뽀모도 (🔒 2026-09-26 추가 CR-045) | 선택 `pomo_char`·`pomo_bubble` + 앱이 그리는 시간 글자 | 전체 캔버스 | 배경처럼 고정. §6 뽀모도 타이머 |
| 5 | 몸통 | 선택 1장 `body` (🔒 2026-09-23 필수 → 선택, 설정 창 카드 없음 — 🔒 2026-09-24) | 전체 캔버스 | 본체 묶음의 맨 아래. 있으면 항상 표시. 캐릭터 본체는 보통 `kb_up`에 그린다 |
| 6 | 일반 상태 | 대기 `idle` / 쉬는중 `rest` 각 1장, **선택** (🔒 2026-09-24 키연타(쾅) 폐기, 선택 강등) | 전체 캔버스 | 상태에 따라 교체. 몸통과 키보드 그림 **사이**에 깔리는 표정·효과. 비어 있으면 투명 |
| 7 | 키보드 파츠 | 들림 `kb_up` 1장(**필수**, 디폴트 상태 — 캐릭터 전체를 그려도 된다), 누름 `kb_down_N`(선택, 여러 장이면 순환), 특수 키 `key_*`(선택) | 전체 캔버스 | 키 누르면 누름으로 교체 + 바운스, 떼면 들림. 연타 시 누름 이미지 순환. **바운스 = 젤리(🔒 2026-09-24, CR-022):** 키 누름(바운스 트리거는 기존 규칙 그대로) 때 **배경을 뺀 모든 레이어(몸통·일반 상태·키보드 파츠·마우스 파츠)가 한 덩어리로** 캔버스 아래 가운데 기준 스쿼시 앤 스트레치 — 눌림(세로↓·가로↑) → 늘어남 → 2~3회 감쇠 출렁임, 약 0.35초, **세기 보통**(첫 눌림 세로 약 −8%·가로 약 +6%). 배경은 움직이지 않음. **키 꾹 누름(OS 자동 반복) = 부르르(🔒 2026-09-24, CR-023):** 어떤 키든 누른 채 자동 반복 입력이 들어오는 동안 같은 덩어리(배경 제외)가 **작고 빠르게 계속 떨림**(약한 세기, 짧은 주기 반복), 키를 떼거나 반복이 멈추면 정지. 처음 누름은 기존 젤리. **Shift·Ctrl·Alt·Win(좌우)만 꾹 누를 때는 떨지 않음**(🔒 2026-09-24 — hook이 수식 키의 자동 반복을 반복 신호로 내보내지 않음) |

Rust(core assets)가 계산해 bridge로 넘긴다. 자동 계산이 실패할 때만 `mouse.hand`(기본 없음)를 폴백으로 쓴다. 클릭 이미지도 같은 기준점. 기준점은 그림 좌표 + `partPos`로 캔버스 좌표가 된다. 입력이 없을 때(앱 시작 직후·쉬는중)는 회전 0°·배율 1(그린 그대로). 클릭 시 이미지 교체(펜 모드에서는 CR-027 규칙) |
| 8 | 펜 손 (🔒 2026-09-24 CR-024, 2026-09-25 단순화 CR-042) | 선택 `pen_up`·`pen_down_0` | 파츠(크기 자유) + `penPos` | 본체 위. 팔 끝에 붙어 이동·기울기만 따르고 크기는 불변. 펜 모드 규칙은 §3 |

- 오버레이 창 위치는 이동이 끝나면 core window가 저장하고 시작 시 복원한다(R-13).

- **필수 이미지 2장: `kb_up`, `mouse_base`**(🔒 CR-043 최종). 이력: 필수 6장(body·idle·rest·slam·kb_up·kb_down_0) → 몸통 선택(2026-09-23) → 쾅 폐기로 4장(2026-09-24) → idle·rest 선택 강등 + `mouse_base` 필수(설정 창 개편 2026-09-24) → `kb_down_0` 선택 강등(2026-09-26). 나머지 슬롯은 모두 선택.
- "둘 다" 상태용 이미지는 없다. 레이어가 독립이라 키보드 손과 마우스 손이 동시에 각자 움직인다.
- 예시 몸통 이미지: `doc/assets/samples/body.png` (900×700 RGBA 89 KB, 2026-09-23 사용자 제공). `src-tauri/tests/sample_assets.rs`가 이 파일이 규격을 통과함을 검증한다. `dist/`는 빌드 산출 폴더라 원본을 거기 두지 않는다.
- 마우스 파츠 설정값(`mouse`, 설정 창 「어깨축·손 위치」 탭 미리보기에서 지정):

## 5. 상태 전이 (🔒)

| 상황 | 상태 레이어 | 키보드 파츠 | 마우스 파츠 |
|---|---|---|---|
| 아무 입력 없음 | 대기 | 들림 | 쉬는 자세(회전 0°·배율 1, 그린 그대로) |
| 5분(설정값, 60~3600초) 무입력 | 쉬는중 | 들림 | 쉬는 자세 |
| 키 입력 | 대기 | 누름(바운스) → 들림 | 유지 |
| ~~동시에 6개 이상의 키가 눌려 있음~~ | **🔒 2026-09-24 쾅 메커니즘 폐기** — 사용자: 빠른 타자와 쾅쾅쾅 연타를 입력으로 구분할 수 없음(키 기록 분석: 연타도 30~40ms 안에 4~6키, 타자와 겹침). 상태·설정(`slam`)·이미지 슬롯(`slam`) 모두 삭제 | — | — |
| 마우스 이동 | 대기 | 들림 | 커서 따라 이동 |
| 마우스 클릭 | 대기 | 들림 | 클릭 이미지로 교체 |
| 둘 다 | 레이어별 규칙 독립 적용 | 누름 | 커서 따라 이동 |

- 감지 범위: 키보드는 **누름·뗌 + 동시에 눌린 키 수**(어떤 키인지는 훅 모듈 밖으로 나가지 않음).
- **바운스 시작 규칙 (🔒 2026-09-30 사용자 지정, CR-066 — CR-027 「이미 누르고 있으면 재생 안 함」 대체):** 새로 누른 키(자동 반복 아님)는 **매번** 바운스(젤리)를 다시 시작한다 — Shift·Ctrl 같은 다른 키를 누른 채여도, 마우스 버튼(펜 모드 클릭 포함)을 꾹 누른 채여도. 사용자 피드백: 게임 중 마우스 버튼을 누른 상태에서 키보드를 치면 탱글거리지 않았다. 자동 반복(꾹 누름 반복 신호)은 여전히 바운스를 다시 시작하지 않고 부르르(CR-023) 규칙은 그대로. **마우스 클릭도 같은 규칙(🔒 2026-09-30 추가):** 펜 모드에서 새 클릭(누름)은 키를 누른 채여도 매번 바운스를 다시 시작한다(옛 「누른 게 없을 때만」 대체).
- **특수 키 이미지 (🔒 2026-09-24 사용자 지정, CR-021):** 6종 — 스페이스바 / ㅋ·z·Z(같은 물리 키 Z) / ?(Shift+`/`) / !(Shift+`1`) / Enter / Backspace. **+ Ctrl+Z(「뒤로가기」, 🔒 2026-09-24 추가 — 7종).** **Ctrl을 누른 채 누르면 Ctrl+Z 외에는 특수 키가 아니라 일반 키 누름**(예: Ctrl+Enter). Ctrl+Z는 ㅋ 그림이 아니라 뒤로가기 그림. **특수 키가 새로 눌릴 때마다 바운스**(다른 키를 누르고 있어도). 여러 특수 키를 동시에 누르면 가장 나중에 누른 키의 그림, 그 키를 떼면 아직 눌린 이전 특수 키 그림. 해당 키를 **누르고 있는 동안** 그 키 전용 그림(캔버스 전체 크기, 규격은 §3 그대로)으로 교체하고 **바운스**, 떼면 `kb_up`. 전용 그림은 **선택**(필수 아님) — 없으면 일반 키 누름 그림(`kb_down`)으로. 훅 모듈은 **이 6종인지 여부(분류값)만** 밖으로 내보내고, 그 밖의 키는 "알 수 없음"으로 둔다. **입력 내용은 절대 기록하지 않는다**(파일·로그·메모리 저장 금지). 마우스는 **이동 + 좌/우 클릭**.

## 6. 창·부가 기능 (🔒)

- 오버레이 창: 투명 배경, 테두리 없음, 항상 위, 드래그로 위치 이동, 위치는 설정에 저장. 창 크기 = 현재 표시 크기(§3). 배율이 바뀌면 core window 모듈이 창을 같은 크기로 리사이즈한다.
- 트레이 아이콘: 메뉴(설정 열기 / 새로고침 / 오버레이 표시·숨김 / 종료, 스톱워치·타이머가 켜져 있으면 맨 위에 시작|일시정지·멈춤 — 아래 CR-046·CR-048).
- **오버레이 오른쪽 클릭 메뉴 (🔒 2026-09-29 사용자 피드백·결정, overlay R-40, 설계 `doc/200_설계/architecture/overlay-context-menu.md`):** 오버레이 창 위에서 오른쪽 버튼을 누르고 떼면(누른 곳·뗀 곳 모두 창 사각형 안, 투명 부분 포함) 커서 위치에 **트레이와 같은 메뉴**(항목·순서·동작 동일)가 뜬다. 위치 잠금 중에도 뜨며(전역 훅으로 감지) 그 클릭은 아래 창에도 전달된다(막지 않음). 오버레이 숨김이면 안 뜸. **다른 프로그램이 전체 화면(전경 창의 클라이언트 영역이 모니터 전체를 덮음)이면 안 뜸.** 메뉴가 뜨면 전경 창이 포커스를 잃는 것·아래 창 메뉴와 겹치는 것은 수용. 브라우저 기본 오른쪽 클릭 메뉴는 없앤다.
- 설정 창: 오버레이와 **별도 창**. 이미지 등록·미리보기, 배율, 유휴 시간, 마우스 파츠 위치, 자동 실행 옵션.
  - **어깨축 설정 마법사(🔒 2026-09-23)**: 「어깨축·손 위치」 탭(옛 「마우스 파츠」 탭) → 미리보기(바탕 = 몸통이 있으면 몸통, 없으면 `kb_up` + 팔 그림을 `partPos`에 합성, 축 표시. 옛 패드 박스·손 점은 없음 — CR-006·CR-016. 팔·펜 손 영역의 파란·빨간 상자는 CR-040). **손 그림 끌어다 놓기(🔒 2026-09-23, CR-016)**: 마법사가 idle일 때 미리보기의 손 그림을 끌어 놓으면 `partPos`가 저장된다. 그림 전체가 캔버스 안에 들어오게 제한(전체 크기 그림은 (0,0) 고정). → 「어깨축 설정하기」 → **한 단계**(CR-005): "축이 될 부분을 마우스로 클릭해주세요" → 검토 "축 위치를 확인하고 저장하세요." → 저장/취소. 손 위치 단계·뒤로 버튼·손 위치 표시는 없다. 「기본값으로 리셋」은 확인 창 없이 코드 기본값(§4 마우스 파츠 설정값 표 — 어깨 582,484 · 이동 영역 · 팔 411,464 · 손 372,476 · `hand` 없음)으로 되돌리되 `penMode`는 유지한다(CR-033). 사용자 설정은 settings.json에 저장되고 기본값은 코드(Rust `settings::default_mouse`, TS `DEFAULT_MOUSE_SETTINGS`)에 있다.
- 시작 시 자동 실행: 옵션(기본 꺼짐). **방식 = 작업 스케줄러, 🔒 2026-09-26 변경(CR-047): 일반 권한(LeastPrivilege)으로 실행 — 보안 검토 SEC-001(관리자 자동 실행 + 사용자 쓰기 가능 exe = 권한 상승 경로) 때문에 관리자 자동 실행 폐기. 관리자 게임 안 입력이 필요하면 사용자가 직접 관리자로 실행.** (이전: 관리자 권한, 🔒 2026-09-24) — 관리자로 실행된 게임 안에서도 입력을 받기 위함(UIPI).
- **설정 창 개편 (🔒 2026-09-24 사용자 지정, R-set-v2):** 참고 화면 = 사용자 제공 스크린샷 2장(카드형 섹션, 알약형 탭, 초록 강조색, 토글 스위치, 이미지 카드에 「이미지 변경」·「기본값」 버튼). 참고 제품의 이름·제작자 표기는 가져오지 않는다. 탭 3개:
  1. **기본 설정**: 언어 선택(한국어 / 일본어 / 영어 — 설정 창 전체 문구 3개 국어) · **위치 잠금** 토글(켜면 오버레이가 마우스 클릭을 통과시키고 끌어서 옮길 수 없음) · **작업표시줄 표시** 토글 · **컴퓨터 시작 시 자동 실행** 토글 · **위치 초기화** 버튼(오버레이를 기본 자리로). 참고 화면의 크기·흔들림·항상 위·머리글·닫기·설명서·프리셋은 넣지 않는다(→ 프리셋은 2026-09-30 사용자 요구로 **별도 탭**으로 추가 — 아래 「프리셋」 항목 PS-01~PS-10. 참고 화면의 프리셋 UI를 옮기지 않는다는 뜻만 남는다).
  2. **이미지 설정**: 배경 / 키보드(본체 겸) / 팔(마우스) / 손(펜). 필수 = 키보드 기본(`kb_up`) + 팔(`mouse_base`) — `kb_down_0`은 CR-043에서 선택으로 강등(당시 결정은 `kb_down_0`도 필수였다). 대기(idle)·쉬는중(rest)은 **선택으로 강등**(없으면 투명). 배경·손·특수 키·클릭 그림은 선택.
  3. **어깨축·손 위치**: 기존 「마우스 파츠」 탭(어깨축 마법사, 팔·손 끌어다 놓기, 이동 영역).
  - **기본 이미지 세트 (🔒 2026-09-24 사용자 지정, CR-035 — 시딩·「기본값」 복원·다운로드 규칙은 유효, 그림 목록과 좌표는 CR-038 → CR-044 → CR-053이 차례로 대체. 현재 목록은 CR-053):** 2026-09-24 현재 등록된 15장(background·idle·rest·kb_up·kb_down_0·key_* 7·mouse_base·pen_up·pen_down_0, 원본 `doc/assets/defaults/`)을 **앱에 내장한 기본값**으로 삼는다. 첫 실행(또는 슬롯이 비어 있을 때) 이 세트로 채운다. 카드의 「기본값」 = **내장 기본 그림으로 되돌리기**(사용자 그림 삭제 후 기본 복원). 내장 기본이 없는 칸(mouse_left/right, pen_key_*, kb_down_1+, pen_down_1+)은 지금처럼 **비우기**. 이미지 설정 탭에 **「기본 이미지 다운로드」 버튼**: 폴더를 고르면 내장 PNG 전부를 **원본 크기 그대로** 슬롯 파일명(`kb_up.png` 등)으로 저장 — 사용자가 트레이싱·리터칭용으로 쓴다. 특수 키 7장(임시 글자 그림)도 기본 세트에 포함. **결정(🔒 2026-09-24):** 기본 그림이 있는 칸은 **비우기 없음**(「기본값」은 복원만, 캔버스 크기 교체는 그림 교체로). 펜 손 위치 기본값 `penPos` = **(380, 496)**(끌어다 놓은 좌표를 코드 기본값으로). 다운로드 폴더에 같은 이름 파일이 있으면 **확인 후 전부 덮어쓰기**. penMode 기본 false 유지, 시딩은 매니페스트가 비어 있고 슬롯 파일이 없을 때 15장 전부, 내장은 `include_bytes!`, 빈 `pen_up` 복원 시 R-30 확인창.
  - **팔·손 파츠 크기 자유 (🔒 2026-09-25 사용자 지정, CR-036):** 팔 파츠(mouse_base·mouse_left·mouse_right)끼리, 손 파츠(pen_up·pen_down_N·pen_key_*)끼리 **같은 크기 규칙을 없앤다.** 각 그림은 상한(≤900×700, 1 MB, PNG 32bit)만 지키면 크기가 제각각이어도 등록된다. 위치는 어깨축·손 위치 탭에서 조정. 캔버스 레이어(배경·키보드·대기·쉬는중·특수 키)끼리 같은 크기 규칙은 유지.
  - **헤어(뒷머리) 파츠 (🔒 2026-09-25 사용자 지정, CR-037):** 장발 캐릭터의 뒷머리가 본체에 그려지면 팔·손이 가려지므로 뒷머리만 따로 그린 **`hair` 슬롯**을 둔다. **캔버스 레이어**(900×700 등 배경·키보드와 같은 크기, 위치 조정 없음), **1장 고정**(상태·키 입력으로 바뀌지 않음), **선택**(필수 아님, 내장 기본 그림 없음 → 「기본값」=비우기). 겹침 순서(아래→위): **배경 → 헤어 → 팔·손 → 본체(키보드 그림)**. 젤리·부르르는 본체와 한 덩어리로 함께(배경만 고정).

    - PS-02 **들어가는 것**: 등록된 그림 **전부**(매니페스트의 모든 슬롯), 알림음(있으면), 배율, 휴식 시간(idleSeconds), 어깨축·이동 영역·팔 위치·손 위치·펜 모드(`mouse` 전체), 타이머 설정 전체(모드·시간·음량·글자 위치·회전·크기·색·on/off).
    - PS-03 **안 들어가는 것(PC별 설정 — 적용해도 그대로)**: 오버레이 창 위치·표시 여부, 자동 실행, 언어, 작업표시줄 표시, 위치 잠금.
    - PS-04 **적용**: 목록에서 골라 「적용」 → 확인창 → 현재 그림·알림음·설정을 프리셋 것으로 **통째로 교체**(프리셋에 없는 슬롯은 비워짐) → 오버레이·설정 창 즉시 반영(기존 `assets://changed`·`settings://changed`). **자동 백업 없음** — 지금 상태를 남기려면 사용자가 먼저 저장한다(확인창 문구로 안내).
    - PS-05 **내보내기**: 프리셋 하나를 사용자가 고른 위치에 **폴더째** 복사(파일 형식 = 저장 폴더와 동일). 압축은 사용자가 직접 한다. **새 의존성 없음**(zip 크레이트 사용 안 함, 🔒 2026-09-30 결정).
    - PS-06 **가져오기**: 폴더를 골라 프리셋으로 등록 → 목록에 뜬다. PNG는 기존 규격 검사(32bit RGBA·상한·캔버스 일치)를 통과해야 하고, 알림음은 기존 형식·1MB 규칙. 실패하면 어느 파일이 왜 안 되는지 알려주고 아무것도 등록하지 않는다(부분 등록 없음). 폴더 안 경로는 프리셋 폴더 밖을 가리킬 수 없다(보안).
    - PS-07 **목록 관리**: 이름 바꾸기·삭제(확인창). 이름 중복 허용(id로 구분), 빈 이름 불가.
    - PS-08 **저장 조건**: 필수 그림 2장(`kb_up`·`mouse_base`)이 없으면 저장 버튼 비활성 + 이유 표시(그림 없는 프리셋은 만들지 않는다).
    - PS-09 **화면**: 설정 창 새 「프리셋」 탭(사이드바 다섯째). 위 = 「현재 상태를 프리셋으로 저장」(이름 입력) + 「폴더에서 가져오기」, 아래 = 프리셋 카드 목록(이름·저장 날짜·그림 장수·알림음 유무, 버튼: 적용·내보내기·이름 바꾸기·삭제). 문구는 한국어·일본어·영어.
    - **PS-09 개정 (🔒 2026-09-30 사용자 지정, CR-065 — 카드 모양):** 프리셋 목록은 가로로 긴 줄이 아니라 **세로형 카드 격자**다. 카드 위쪽 = 그 프리셋의 그림 **미리보기(오버레이 전체 그대로 — 뒷머리·배경·뽀모도 인물·말풍선·팔(partPos)·펜 손(penPos, 쉬는 자세 회전 0°)·본체 kb_up을 오버레이 겹침 순서로 합성, 시간 글자 없음)**, 아래 = 이름·저장 날짜·그림 장수·알림음 유무·버튼 4개. 미리보기는 프리셋 폴더의 PNG를 직접 보인다(asset protocol scope에 `presets/**` 읽기 추가 — 사용자 승인 2026-09-30). 초기 설계의 「썸네일 없음」은 이 개정으로 폐기.
    - **PS-11 내장 프리셋 (🔒 2026-09-30 사용자 지정, 0.5.0):** exe에 프리셋 2개를 내장한다 — ① 「세바시에-기본」(그림 6장 = 배포용 기본 세트 4차와 바이트 동일 + 기본 알림음, 타이머 글자 (268,402)·7°) ② 「게님드림」(그림 7장 — hair 포함, 기본 알림음, 타이머 글자 (142,456)·11°). 원본 `doc/assets/presets/1`·`2`(preset.json 포함, 사용자 저장본 그대로; 재현 목록 `_inventory.txt`). **시딩 규칙:** 앱 시작 시 `presets/` 폴더가 **없을 때만**(첫 실행·0.4.0에서 올라온 설치) 두 프리셋을 `presets/builtin-1`·`presets/builtin-2`로 쓴다(savedAt = 원본 값). 폴더가 있으면(비어 있어도) 건드리지 않는다 — 사용자가 지운 것을 되살리지 않기 위해. 전체 초기화·세대 초기화는 프리셋을 건드리지 않는다(U-1 유지). 내장 기본 그림 세트(4차)·`DATA_GENERATION`(5)은 **바뀌지 않는다**(프리셋 ①이 기본 세트와 같으므로 초기화 불필요). 버전 0.5.0.
    - PS-10 **적용 후 상태**: 프리셋과 현재 상태는 별개다(캐릭터를 골라 복사해 오는 것). 적용 뒤 현재 상태를 바꿔도 프리셋은 안 바뀐다. 「지금 어떤 프리셋을 쓰는 중」 표시는 두지 않는다.

## 8. 계층 위상과 경계

```
ui (React)  →  bridge (Tauri command·event 계약)  →  core (Rust 모듈)
```

- **단방향**. ui는 `src/bridge/`의 래퍼만 호출한다. `invoke`·`listen`을 화면 코드에서 직접 쓰지 않는다.
- bridge 계약(`doc/200_설계/bridge/contract.md`)이 TS 타입(`src/bridge/types.ts`)과 Rust 구조체(`src-tauri/src/bridge/`)의 단일 소스다. 셋이 어긋나면 bridge 결함.
- core 모듈은 ui를 모른다. core는 bridge를 통해서만 이벤트를 밖으로 낸다.
- ui 작업 중 계약 변경이 필요하면 ui는 고치지 않고 **bridge 요구 명세**를 만들어 사용자에게 보고한다. 허락 후 bridge-manager 세션으로 인계한다.
- bridge 작업 중 core 변경이 필요하면 같은 방식으로 core-manager 세션으로 인계한다. 단, **구축(build) 모드**의 task-manager는 세 계층을 한 흐름으로 만든다.

## 10. 공통 규범 (모든 에이전트 본문에 반영)

- 문서·에이전트 본문은 **한국어**.
- **보고 채널은 하나**: 서브에이전트는 최종 응답 1회로 보고한다. SendMessage로 중간 보고하지 않는다.
- **실행 예산**: 위임문의 `예산: 도구 호출 N회 · 벽시계 M분`을 지킨다. 기본값은 구현 N=80·M=30, 설계 N=50·M=20, 검증·분석 N=30·M=10. 초과 시 진행 보고(`상태: 예산 초과 | 완료 | 미완료 | 막힌 지점 | 잔여 예상 | 권고`)로 반환.
- **증거 기반 완료**: "될 것이다" 금지. cargo test·vitest 결과, 빌드 exit code, 스크린샷 경로로 증명.
- **요구 범위 준수**: 요구ID로 역추적되지 않는 기능·필드·버튼 추가 금지.
- **라이브러리 설치 허가제**: 새 의존성은 메인 세션에서 사용자 승인 후에만.
- **검증자 독립성**: checker·tester·reviewer에는 「적용 메모리」를 전달하지 않는다. 문서·소스·실행 결과만 근거.
- **모드 판별**: 작업 수신 시 구축(build)/보강(maintain)을 먼저 판별한다.
- 안단테 고유 개념(모드 F/D/P, upstream, cherry-pick, GraphQL, Django, HTML 문서, client/·server/ 경로)은 **어디에도 남기지 않는다**.
